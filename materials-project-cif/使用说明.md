# Materials Project 按元素批量下载 CIF

制作日期：2026-11-03，当前版本 1.0.2。默认模式按你的选择设置为“全部子体系”。

## 1.0.2 修复：支持 MP 字母编号 AlphaID

MP 当前可能返回 `mp-aaaaaafe` 这样的字母编号。它与旧数字编号是同一套标识的不同表示，不是错误数据。1.0.1 把编号限定成数字，导致材料已查询成功后仍被本工具拒绝。

1.0.2 同时支持数字与小写字母编号，并处理材料清单与结构查询响应使用不同表示的情况。例如 `mp-134`、`mp-fe`、`mp-aaaaaafe` 会识别为同一材料，避免“清单是数字、结构返回字母”时误报缺失；CSV 与 CIF 文件名保留清单返回的原始编号。同一编号的不同写法不会重复下载，不同材料编号的晶型继续分别保留。

本工作区原工具目录中的主程序已直接更新。关闭旧报错窗口，再双击原 start.bat，应显示“工具版本：1.0.2”。其他解压位置只需替换同名 download_cif.py。现有 .venv 与下载目录继续使用，不需要重装依赖或因为此错误更换 Key。

## 1.0.1 修复：HTTP 422 / exclude_elements 过长

此前 1.0.0 为了检索全部子体系，提交了所有其他元素的排除列表，超过服务端对 exclude_elements 的 60 字符上限。1.0.1 改为枚举输入元素的全部非空化学子体系，并按请求长度分批查询，不发送这个长排除列表。Al Mg Si Cu 会完整查询 15 个子体系，下载范围不变。

已使用旧参数和服务端长度规则复现 422，并核对官方服务端实现；新查询的回归检查和真实已安装 mp-api 客户端参数序列化检查通过。参数类 400/422 等错误直接报告，不再重复相同请求。

该修复包含在当前 1.0.2 中，下载范围和现有环境保持兼容。

## 这个工具做什么

输入元素符号后，通过 Materials Project 官方 API 查询材料，再用 pymatgen 把结构导出成 CIF。

例如输入 `Li Fe O`，下载数据库中属于以下体系的全部匹配材料：

- 单质：Li、Fe、O。
- 二元：Li–Fe、Li–O、Fe–O。
- 三元：Li–Fe–O。

不会下载含其他元素的材料，例如 Li–Fe–P–O。不同配比、不同晶型分别保留；不按化学式去重。输入 `Si` 时下载纯 Si 的匹配晶体结构；不会把所有含 Si 的化合物都算入。

输入是元素列表，不是化学式：用 `Li Fe O` 或 `Li-Fe-O`，不要输入 `LiFeO2`。脚本也支持中文/英文逗号分隔和去除重复元素。

## “全部”的具体范围

- 默认下载当前 API 中匹配的、未被标记为 deprecated（弃用）的材料；包含稳定和不稳定结构，不设置总数量上限。
- 每个材料编号（例如 mp-149）对应一份 summary 结构 CIF。不同编号、相同化学式仍保留。
- 当前 API 能访问的弃用条目可用 `--include-deprecated` 加入；无法保证访问所有历史已移除条目。
- 不是下载材料的全部初始结构、弛豫中间帧、历史 task 或原始实验 CIF。导出的结构来自 API 的 structure 字段，可能是计算弛豫后的结构。
- CIF 不包含训练所需的完整能量/受力标签，也不包含 POTCAR 赝势。下载后如要训练 NEP，还要按项目流程完成结构准备和 DFT 标注。
- 只从数据库取结构，不运行 VASP、NEP 或 GPUMD；不需要 DCU。运行机器需要能够联网访问 MP。

## 第一次准备：API Key

1. 注册并登录 https://materialsproject.org/ 。
2. 打开账号 Dashboard：https://materialsproject.org/dashboard ，找到自己的 API Key。
3. 第一次运行时在终端粘贴 Key。输入不显示，粘贴后按回车即可；工具不会把 Key 写入输出文件。

如果终端粘贴无反应，输入不显示是正常情况；可以右键粘贴或使用该终端支持的粘贴快捷键。

## 平时怎么运行

完成上面的准备后，直接双击 `start.bat`。

依次输入：

```text
请输入元素符号，用空格分开（例如 Li Fe O）： Li Fe O
请输入 Materials Project API Key（不显示，也不保存）： [粘贴自己的 Key 后按回车]
```

文件会放在工具目录下新建的 `MP_CIF_Fe-Li-O_subsystems` 文件夹中。元素顺序会标准化；你输入 O Fe Li 会使用相同目录，不会重新下载一遍。

也可以在工具目录的 CMD 中直接指定元素：

```bat
.venv\Scripts\python.exe download_cif.py Si
.venv\Scripts\python.exe download_cif.py Li Fe O
.venv\Scripts\python.exe download_cif.py Cs Pb I -o CsPbI_structures
```

如果不是使用本工具的 .venv，可在已经装好依赖的 Python 环境运行 `python download_cif.py Li Fe O`。

Windows 入口按以下顺序选择 Python：环境变量 MP_CIF_PYTHON → 同目录 .venv\Scripts\python.exe → PATH 中的 python。

## Linux / 超算

在能访问 Materials Project 的登录节点或普通联网电脑使用即可；不需要 sbatch。超算是否允许登录节点联网取数据，以实际平台规则为准；不能联网时可在本机下载后上传 CIF。

## 其他检索模式

下面以已经激活正确 Python 环境为例；若使用 .venv，将 python 换为相应 .venv 中的 Python 路径。

```bash
# 默认：Li、Fe、O 所有子体系
python download_cif.py Li Fe O

# 只要同时含 Li、Fe、O，且没有其他元素的三元材料
python download_cif.py Li Fe O --mode exact

# 必须同时含 Li、Fe、O，但允许 P、F 等其他元素
python download_cif.py Li Fe O --mode contains

# 只下载 MP 标记为热力学稳定的材料（默认不做这个限制）
python download_cif.py Li Fe O --stable-only

# 加入当前 API 仍可访问的弃用条目
python download_cif.py Li Fe O --include-deprecated

# 先只查清单，不导出 CIF；之后去掉 --list-only 即可按该清单下载
python download_cif.py Li Fe O --list-only

# 指定输出目录；可在路径有空格时加引号
python download_cif.py Li Fe O --output "D:/MP structures/Li-Fe-O"

# 查看全部参数，不需要 API Key，也不需要先导入第三方依赖
python download_cif.py -h
```

`--batch-size 50` 代表每批下载 50 个结构，不是只下载 50 个。默认会读取全部查询分页，随后逐批处理所有匹配材料。

子体系总数为 2 的元素数次方减 1，例如 4 种元素有 15 个子体系。默认 `--max-systems 4095` 最多自动枚举 4095 个子体系；超过时会明确报错，不会偷偷只取一部分。如确需更大的完整枚举，可以显式增加此参数。它限制的是需要查询的化学体系数，不是匹配材料总数。

## 输出怎么看

```text
MP_CIF_Fe-Li-O_subsystems/
  cif/
    Fe/
      Fe__mp-编号.cif
    Fe-O/
      Fe2O3__mp-编号.cif
    Fe-Li-O/
      化学式__mp-编号.cif
    ...
  materials.csv          材料编号、化学式、体系、原子数、空间群、稳定性、路径和下载状态
  download_state.json    查询条件、材料快照和续传检查点，请保留
  report.json            匹配/成功/失败数量及是否全部保存
  failed.json            导出失败的编号和原因；全部成功时为空列表
  .download.lock         防止同目录多个进程同时写入；文件保留是正常的
```

示意文件名中的“编号”不是实际下载结果。MP 数据量随数据库更新、元素和筛选条件变化；某些子体系可能没有条目。

为保留 API 提供的晶胞和全部坐标，导出时不重新做对称化，CIF 可能以 P1 表示完整结构；这不代表材料真实空间群变成 P1。API 条目的空间群另保存在 materials.csv 的 spacegroup 列。

终端结束时应显示“失败：0；待下载：0”。report.json 中的 `all_matched_cifs_present=true` 表示本次清单对应的文件均已保存；零匹配时也要看 `matched_materials`，它会明确为 0。

## 中断、续传与重新查询

- 中断后重新执行相同命令、使用同一输出目录，会读取已保存的清单，校验 CIF 的 SHA-256，跳过完整文件，只重试未完成或损坏的工具输出。
- 同一元素列表的顺序改变不会导致重下；同一化学式不同 MP 编号不会互相覆盖。
- CSV/JSON 清单不要手工改。输出目录应是本工具专用目录，不要存放其他原始资料。
- 默认续传沿用首次查询的材料编号清单，不自动新增后来出现的材料编号。尚未下载的结构来自续传时 API 的当前数据，本工具没有锁定远端数据库版本。如果下载跨越数据库更新，或希望重新查询最新材料，请用 `--output` 指定新目录重新下载整套，例如 `--output LiFeO_new`。
- 更改模式、稳定性或弃用筛选条件时，默认输出目录可能已经存在；若提示查询条件不同，请用新的 `--output`。不会擅自覆盖其他条件的下载集。
- 429/超时会有限重试；整批接口仍失败时停止并保留成功结果。单个结构不可用/导出失败会记录编号，继续处理其他结构，退出码为 1。
- 不做无限重试，也不会把仅部分成功描述成全部成功。

## 可选：当前终端读取环境变量中的 Key

如果不想每次手输，可在自己的当前终端设置 `MP_API_KEY`。不建议把真实 Key 写进共享脚本或 Slurm 日志。

```powershell
$env:MP_API_KEY = "在自己电脑上替换为真实Key"
```

```bash
export MP_API_KEY='在自己终端替换为真实Key'
```

这些命令只影响当前终端及其子进程。非交互运行（例如输出重定向、计划任务）必须提供元素参数和 MP_API_KEY。
